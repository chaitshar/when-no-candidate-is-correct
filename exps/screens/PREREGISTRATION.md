# Screening portfolio preregistration (S1 to S10), 2026-11-03 ~22:45 UTC, before any screen data

Screens are exploratory. A screen is never reported as a finding; survivors go to a prior-art check and then to a confirmatory study on fresh locked items. Every screen has a ledger row. Multiplicity: the final paper corrects across the whole ledger.

## Shared items and stage G (generation)
Bank: gen/progtrace.py (justification in exps/s0_calibration/PREREGISTRATION.md). For each model m the difficulty L_m is the level chosen by S0 (solve rate closest to 0.5 within [0.2, 0.8]). Screen seeds: 200000 to 299999. Stage G: for 120 tasks at L_haiku, haiku solves each task 6 times (SOLVE prompt, isolated calls). For 40 tasks at L_sonnet (if sonnet is calibrated), sonnet solves each 3 times. A candidate is one solver reply; it is wrong iff its parsed integer differs from the executed answer. Distinct wrong answers per task form target-absent (TA) pools of 3; TA pools plus one right reply (if any) minus one wrong form TP pools. Order seed f"S-{tid}-{kind}". Judges see code, candidate reasoning and candidate final answer.

Judges: haiku (all screens); sonnet only where stated, within 3 USD per screen. Resolved model id recorded per call. No opus or fable in screens.

## Screens (mechanism, primary metric, kill rule)
S1 Rejection channel in selection (lineup, B1 on fresh items). Arms ISO, PICK (with NONE), FORCED (no NONE) on TA and TP pools. Primary: TA choosing PICK minus ISO-any, paired by task, bootstrap 95% CI. Kill: |diff| < 0.05 and CI within +-0.15.
S2 Field-claim retest: agreement among self-consistency samples as a confidence signal (Wang et al. 2022 self-consistency; widely used to gate answers). Data: stage G samples only (no new calls). Primary: AUROC of the majority answer's vote share for predicting that the majority answer is correct, per model; and the rate at which a strict majority (>= 4 of 6) is wrong. Kill (claim holds): AUROC >= 0.75 and strict-majority-wrong rate < 0.10. Surprise if AUROC < 0.65.
S3 Tournaments on fresh items (B2): every ordered pair of a pool in a forced-choice call, TA and TP pools. Primary: AUROC of decisiveness for TP vs TA, problem-clustered bootstrap. Kill: AUROC CI lower bound >= 0.75 (tournaments do carry an absence signal).
S4 Causal effect of checkable critiques (mediation, B-line). Each candidate (right or wrong) is judged with an attached critique of the form "At the end of iteration k, variable v is X, not Y as the solution states/implies". Factors, randomized per item: critique VALID (true value per execution trace, points at a real discrepancy, only possible on wrong candidates) vs INVALID (false value), and source label "an automated checker" vs "another student" (label swap). Plus a no-critique control. Primary: acceptance of right candidates with an INVALID critique minus with none (harm of invalid critiques), and rejection of wrong candidates with a VALID critique minus none (benefit). Mediation estimate: share of the label effect that disappears when validity is held fixed. Kill: both effects within +-0.05.
S5 Failure attribution by counterfactual replay (field claim retest: LLM failure attribution in multi-agent logs, Who&When 2505.00212 style). Two-agent chain: agent A traces iterations 1..ceil(L/2) and reports the state; agent B gets the code and A's state and finishes. Ground truth by replay: A is at fault iff its handoff state differs from execution; B is at fault iff its final answer differs from executing the remainder from A's handoff. An attributor (haiku; sonnet if budget) reads the two transcripts and names the faulty agent(s). Primary: attribution accuracy on failed runs versus the base rate of the majority class. Kill (claim that LLM attribution works holds): accuracy >= 0.8.
S6 Field-claim retest: decomposition into an agent chain helps long tasks. Single agent traces the whole loop vs a chain of 3 agents each tracing a third with handoffs (same total iterations; compute reported). Primary: final accuracy chain minus single, paired by task. Kill: |diff| < 0.05.
S7 Correlated blind spots among verifiers. ISO verdicts on wrong candidates by haiku repeated twice and by sonnet once (subset). Primary: phi correlation of false accepts across repeats and across models, versus 0. Kill: phi < 0.1.
S8 Weak judge with hidden evidence, debate on target-absent pairs (B3). Two haiku debaters each defend one candidate answer (from the same task) and may quote the code; the judge (haiku) does NOT see the code, only the debate, and answers A, B or NEITHER. Pairs: TP (one right, one wrong) and TA (both wrong). Primary: NEITHER rate on TA pairs; accuracy on TP pairs versus a consultancy baseline (one debater only). Kill: TA NEITHER rate >= 0.5 (judges detect that both are wrong).
S9 Peer-note contamination (memory contamination between agents). The solver gets the task plus a "note left by another agent: f() returns X" with X wrong (a real wrong candidate), X right, or no note. Primary: accuracy with wrong note minus no note. Kill: |diff| < 0.05.
S10 Heterogeneous versus homogeneous verifier panels on real error correlation. From S1 and S7 ISO data: 3-member panels (haiku x3 repeats vs haiku, haiku, sonnet) majority-vote false accept rates against the independence prediction. Primary: excess of panel false accept over independence, per panel type. Kill: no difference between panel types beyond 0.05.

Each screen's own folder holds build.py and analyze.py committed before its data, and any deviation goes to exps/screens/AMENDMENTS.md. Budget per screen 3 USD; screens run haiku first and add sonnet only if the haiku screen is off the floor.
