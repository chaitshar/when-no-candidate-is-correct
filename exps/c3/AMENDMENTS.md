## A1 (2026-11-04T08:36:31Z), before any arm call (stage 1 SOLVE still running; no arm data exist)
Adds a claude-sonnet-5-5 repeat and H3. The sonnet parse pilot (exps/c3_sonnet_pilot) passed its preregistered rule (75 of 75 parsed) with the system prompt extended by "You have no tools and cannot run code. Reason in plain text and end with the requested final line."; that extended prompt is used for every sonnet call in C3. Haiku calls keep the original prompt.
- Sonnet arms: ISO (3 wrong + 1 right where available), PICK, FORCED on the same selected problems, after the haiku arms. Strata stay as defined by HAIKU's solvability (the question is about haiku's competence); sonnet's own solvability is not measured. Sonnet hypotheses: the same four as haiku (H1, H1u, H2s, H2u) with sonnet's verdicts, in a separate Holm family, labelled exploratory-confirmatory for sonnet because strata are defined by another model. Gate for sonnet: the same rule as haiku on sonnet's own ISO data (excluding the 40-per-stratum clause, which is shared).
- H3 (cross-model verification; the paper recommended this without testing it). On selected TA problems with all three ISO verdicts from both models and a parsed haiku FORCED pick: h_same = haiku ISO accept of haiku's pick minus mean haiku ISO accept of the other two; h_cross = the same with sonnet ISO verdicts on the same three candidates. H3: mean(h_same - h_cross) > 0, one-sided problem bootstrap, alpha 0.05 (single test, own family). Confirmed if p < 0.05; refuted if the 95% CI upper bound is below +0.05; else inconclusive. Descriptive: the share of haiku's forced picks that each verifier accepts, and the mirror analysis with sonnet's picks.
- Caps: sonnet ISO 50 USD, PICK 20 USD, FORCED 20 USD.
- analyze_sonnet.py and analyze_h3.py are committed with this amendment.

## A4 (2026-11-04T10:09:19Z), before any A4 call: target-present pools and the EACH arm (response to the round-4 hostile-expert review)
Objection: a higher target-absent choosing rate can reflect a more liberal choosing criterion (that also raises hits) rather than worse discrimination (Wixted and Mickes 2012), and without the EACH arm pooled presentation is confounded with question form. Added arms on the same 227 selected problems: PICK on each problem's target-present (TP) pool (2 of the 3 wrong candidates plus the first right one; locked in banks/locked_c3/pools.json), and EACH on both the TA and the TP pool. Haiku first (caps PICK-TP 4 USD, EACH 10 USD), then sonnet with the A1 system prompt (caps 20 and 40 USD). ISO verdicts already exist for every candidate involved.
Per problem with both pools and all needed verdicts, for each procedure X in {PICK, EACH, ISO}: hit_X = 1 if on the TP pool the right candidate is chosen (PICK) or accepted while no wrong candidate is accepted (EACH, ISO); fa_X = 1 if on the TA pool a wrong candidate is chosen (PICK) or at least one is accepted (EACH, ISO); J_X = hit_X - fa_X.
- H4 (pre-specified, per model, UNSOLVED stratum): pooling reduces discriminability, mean(J_PICK - J_ISO) < 0. One-sided problem bootstrap (10000). Confirmed if p < 0.05 (single test per model, own family, alpha 0.05). If not confirmed while the TA false-choice difference (H1u) stands and hit_PICK - hit_ISO > 0, the paper reports the C3 effect as consistent with a criterion shift.
- H5 (presentation vs question form, UNSOLVED, per model): mean(fa_PICK - fa_EACH) on TA pools, two-sided bootstrap 95% CI, reported as an estimate (no test).
- Descriptive per stratum: hit, fa, diagnosticity ratio hit/fa, J for each procedure; the same on SOLVED.
analyze_a4.py is committed with this amendment.

## A5 (2026-11-04T10:53:57Z), before any A5 call: confidence ROC and a base-rate manipulation (response to the round-5 hostile-expert review)
Haiku only, on all 227 selected problems (pre-registered strata primary; the post hoc audited strata reported as sensitivity). New prompts in harness/lineup_prompts.py: iso_conf (ISO plus CONFIDENCE 1-5), pick_conf (PICK plus CONFIDENCE 1-5), pick_base_most (PICK stating "In this task, most of the problems have no correct solution among those shown"). Arms: PICKC on TA and TP pools, ISOC on the 3 TA wrong candidates and the TP right candidate, BASE on TA and TP pools. Caps: PICKC 8 USD, ISOC 15 USD, BASE 8 USD.
- H6 (lineup ROC; pooling lowers discriminability once the criterion is factored out): on UNSOLVED problems with both pools, build an ROC for each procedure from confidence thresholds t = 5..1. PICKC: hit(t) = share of TP pools where the right solution is chosen with confidence >= t; fa(t) = share of TA pools where any solution is chosen with confidence >= t. ISOC as a procedure: score each candidate +confidence if ACCEPT and -confidence if REJECT; the procedure identifies the candidate with the strictly highest score if that score is positive; hit(t) = right candidate identified with score >= t on the TP pool; fa(t) = any candidate identified with score >= t on the TA pool. Partial area under each ROC (trapezoid from (0,0), linear interpolation) up to the smaller of the two procedures' maximum fa. H6: pAUC(PICKC) - pAUC(ISOC) < 0, one-sided problem bootstrap (10000 resamples, ROC recomputed per resample).
- H7 (criterion moves with instructions): on UNSOLVED TA pools, fa(BASE) - fa(PICK, from C3) < 0, one-sided problem bootstrap. Reported: hit(BASE) - hit(PICK on TP, from A4).
H6 and H7 form one Holm family at alpha 0.05. Confirmed if Holm p < 0.05; otherwise not confirmed (no refutation rule; intervals reported). analyze_a5.py is committed with this amendment.
